# Step 5 — Data-Model Split by Audience (One Owner per Fact) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split the execution data model by *audience* so every fact has one owner: (1) make `RuntimeEvent` the recordable **system-of-record** by adding a server-monotonic `BIGINT` ordering column (`seq`) and making its persistence **transactional** with the state change it records — so Step 10 *can* reconcile-from-event-log later; (2) scope `RuntimeProjectionService` **honestly** as an audience-specific read/analytics model (not execution truth), with **event-payload enrichment** + a **replay-rebuild test** that reconstructs a run's status/progress projection from the event log alone (ordered by `seq`) and asserts it matches the live read; and (3) **slim `TaskRun`** by extracting `context_pack_json` (by-ref + TTL, with a dereference/expiry render fallback) and `policy_decision` to a 1:1 `task_run_details` side table, while **keeping the cost rollup denormalized** on the hot 1:1 row — sweeping every hot-path reader as acceptance.

**Architecture:** Three independent-but-sequenced concern groups. **Group A (RuntimeEvent as system-of-record):** a `seq BIGINT GENERATED BY DEFAULT AS IDENTITY` column on `runtime_events` (server-assigned total order across workers, unlike client `occurred_at`), a `durable=` flag on the two same-session emitters so a state-recording event's persist failure aborts the transaction instead of being swallowed at `debug`, and a documented retention contract (`RuntimeEvent` is the durable record — exempt from the `EvictionService` 90-day hard-delete that only touches `NormalizedEvent`). **Group B (projections scoped honestly):** soften `RuntimeProjectionService`'s present-tense docstrings, enrich the `step_completed`/`run_completed` event payloads with the resulting `status`, and add `rebuild_run_projection(run_id)` that folds the `seq`-ordered event log into `{status, total_steps, completed_steps}` proven equal to `get_active_runs()` for the same run. **Group C (slim TaskRun):** a `TaskRunDetail` 1:1 table (`run_id` PK/FK CASCADE) holding `policy_decision` (durable) + `context_pack`/`context_pack_expires_at` (TTL'd), a `RunDetailStore` upsert/get-with-expiry owner, expand→backfill→dual-write→dual-read→contract migration sequencing, and a TTL eviction sweep that NULLs expired context packs while preserving `policy_decision`. The cost-rollup triad (`input_tokens`/`output_tokens`/`cost_usd`) stays on `task_runs` untouched — it is the hot history-list reader.

**Tech Stack:** Python 3.12/3.13, pytest (async via the repo's home-grown `pytest_pyfunc_call` `asyncio.run` hook — **no pytest-asyncio, no `asyncio_mode`**), SQLAlchemy 2 / asyncpg, Postgres 17 (pgvector image) with JSONB + `GENERATED BY DEFAULT AS IDENTITY`, Pydantic v2, ruff, **alembic (THREE real migrations — the seq column, the `task_run_details` table + backfill, and the contract column-drop)**.

**Source spec:** [`docs/superpowers/specs/2026-06-28-first-principles-rebuild-design.md`](../specs/2026-06-28-first-principles-rebuild-design.md) §6 Step 5 (migration-order entry), §4.8 (Data model — one owner per fact), §6 preamble (schema-touching steps need a per-step in-flight posture + resume-across-deploy test; Step 5 needs a data-migration/backfill plan: expand-contract, dual-read, pre-cutover event-log-gap handling), §7 risks ("Agent reading a stale projection" → split readers by audience, execution-truth reads stay read-your-writes).

## Current-state corrections (verify-don't-trust — confirmed against code 2026-07-06)

Four parallel extraction passes + targeted reads + a live DDL spike established these grounding facts. The spec's §4.8 present-tense and the brief's shorthand carry point-in-time / stale claims; the deltas that matter:

The extraction pass's `routes_system.py:103` entry is a **false positive** — it reads `e.policy_decision` where `e` is an **`AuditLog`** row (`AuditLog.policy_decision` is a separate `String(32)` column, `audit.py:24`), not `TaskRun`. `policy_decision`'s sole `TaskRun` write is `governor.py:101-104` (a dict `{"decision", "risk_level"}`). Readers: `surface_detail_builders/plan.py:86` and `surface_detail_builders/summary.py:102` (both detail-view, single-run, pattern `ctx = (run.context_pack_json if run else None) or {}` — *already* a defensive dereference-with-fallback), plus `graph_executor.py:412` (the refresh reads its own prior pack's `task_summary`). No list-view reader → extracting it introduces **no JOIN on the hot list path**.

PK is `event_id` (ULID `String(64)`, client-generated `revt_…`); the only order signal is `occurred_at` (`DateTime(timezone=True), server_default=func.now()`), which ties within a transaction and skews across workers. `workspace_id` is a NOT-NULL FK (CASCADE); there is **no `user_id` column**. Indexes are all `(workspace_id, …)`. The `seq` column is net-new → one real migration.
6. **There are TWO same-session debug-swallow emitters, plus one separate-session best-effort path** — the spec's "one emitter" is imprecise. (a) `SurfaceEmitter.emit_event` (`execution_surface_emitter.py:71-86`) — used by `dag_runner`/`step_runner` for step/run lifecycle, adds `RuntimeEvent` + `flush()` on the **same session** as the state change, swallows the flush failure at `debug` (`:85-86`). (c) `EventPublisher.emit_runtime_event` (`event_publisher.py:115-141`) — opens a **fresh** `db_factory()` session and commits it, so it is inherently NOT transactional-with-the-state-change and stays best-effort. So `runtime_events` grows **unbounded** today. The retention contract (§6 Step 5) is therefore: *the system-of-record is exempt from hard-deletion* — not "eviction destroys it." (The blast-radius extraction agent's own ledger mislabeled this "TRUE"; its quoted evidence showed `NormalizedEvent`. Verify-don't-trust applies to extraction agents too.)
8. **`RuntimeProjectionService` reads MUTABLE `TaskRun`/`TaskStep`** for `get_active_runs`/`get_blocked_runs`/`get_active_agents`, and `ModelCall` (a separate analytics source) for `get_agent_workload` (`runtime_projection.py:24-272`). Consumer set is **contained**: 5 GET route handlers in `routes_runtime.py` + tests; no cross-service producers. A replay-rebuild is **not feasible today** because lifecycle event payloads are thin (`{"run_id", "step_id"[, "plan_id"|"error"|...]}`) — they lack the resulting `status`. Group B enriches only the two events the run-status/progress projection needs; workload (`ModelCall`) and active-agents (`input_data.capability`) are explicitly **out of scope** for event-sourcing (different sources).
9. **No `BigInteger` / `Identity` / `Sequence` exists anywhere** (`grep src/models/ alembic/versions/` → zero). Existing autoincrement uses `Integer, autoincrement=True` (`WorkspaceMember`, `ObservationStatus`). Step 5 introduces the first monotonic BIGINT — a genuine design decision with an `alembic check` drift gate (Task 1, D-A1).
10. **No 1:1 side-table precedent exists.** `TaskCheckpoint` (`task_graph.py`) is 1:*Many* (per-pause), `Artifact` is 1:Many. The nearest shape is `TaskCheckpoint`'s `run_id` FK CASCADE + workspace FK. `TaskRunDetail` will use `run_id` as its **PK** (FK CASCADE) — the PK *is* the 1:1 key, no separate id column needed.
11. **Real-DB tests use a self-contained `_entity_env()`-style context manager, NOT a `db_session` fixture** (there is none — `grep "def db_session" tests/` → zero). The authoritative pattern (`tests/test_entity_fts_db.py`, mirroring `tests/idempotency/test_ledger_db.py`): a module-level `_db_reachable()` asyncpg probe → `pytestmark = pytest.mark.skipif(not _db_reachable(), …)`; an `@asynccontextmanager async def _env()` building its own `create_async_engine(get_settings().database_url, poolclass=NullPool)` + `async_sessionmaker(expire_on_commit=False)`, seeding FK parents `User`+`Workspace` (from `src.models.users`; `Workspace(workspace_id=…, name=…, owner_user_id=user_id)`, `User(user_id=…, email=…, display_name=…)`), yielding `(factory, workspace_id, user_id)`, and on exit `delete(Workspace)` (CASCADE) + `delete(User)` then `await engine.dispose()`. IDs are `usr_{ULID}` / `ws_{ULID}`. Reference scaffold to copy:

```python
import asyncio
from contextlib import asynccontextmanager

import pytest
from sqlalchemy import delete
from sqlalchemy.ext.asyncio import async_sessionmaker, create_async_engine
from sqlalchemy.pool import NullPool
from ulid import ULID

from src.config.settings import get_settings
from src.models.users import User, Workspace


def _db_reachable() -> bool:
    import asyncpg

    dsn = get_settings().database_url.replace("+asyncpg", "", 1)

    async def _probe() -> None:
        conn = await asyncpg.connect(dsn=dsn)
        try:
            await conn.execute("SELECT 1")
        finally:
            await conn.close()

    try:
        asyncio.run(_probe())
        return True
    except Exception:  # pragma: no cover
        return False


pytestmark = pytest.mark.skipif(not _db_reachable(), reason="Postgres not reachable")


@asynccontextmanager
async def _run_env():
    engine = create_async_engine(get_settings().database_url, poolclass=NullPool)
    factory = async_sessionmaker(engine, expire_on_commit=False)
    suffix = str(ULID())
    user_id = f"usr_{suffix}"
    workspace_id = f"ws_{suffix}"
    try:
        async with factory() as db:
            db.add(User(user_id=user_id, email=f"s5-{suffix}@example.com", display_name="s5"))
            db.add(Workspace(workspace_id=workspace_id, name="s5-ws", owner_user_id=user_id))
            await db.commit()
        yield factory, workspace_id, user_id
    finally:
        try:
            async with factory() as db:
                await db.execute(delete(Workspace).where(Workspace.workspace_id == workspace_id))
                await db.execute(delete(User).where(User.user_id == user_id))
                await db.commit()
        except Exception:  # pragma: no cover
            pass
        await engine.dispose()
```

> **FK-ordering gotcha (Step-4 learning):** when a test seeds a `TaskRun`/`RuntimeEvent` in the *same* `db` block as `User`+`Workspace`, SQLAlchemy's unit-of-work may emit the child INSERT before the `workspaces` INSERT → `ForeignKeyViolationError`. Either `await db.flush()` after the `User`+`Workspace` adds and before the child add, or seed children in a *separate* committed `async with factory() as db:` block (parents are already committed when `_run_env` yields).

## Design decisions (rationale + rejected alternatives)

- **D-A1 — `seq` is `BIGINT GENERATED BY DEFAULT AS IDENTITY`, declared `Identity(always=False)` on the model.** A server-side identity is assigned at INSERT by a single global counter → a true total order across concurrently-writing workers, which `occurred_at` (independent per-worker `now()`) and client ULIDs cannot give. `BY DEFAULT` (not `ALWAYS`) still lets a migration/backfill override values. **Verified live**: ADD COLUMN on the 392-row table backfilled all rows distinct/non-null and new inserts got monotonic values (rolled back). **Historical-order caveat (documented):** on `ADD COLUMN`, Postgres fills existing rows in heap-scan order (≈insertion), not `occurred_at` order — acceptable because only *new* runs are reconciled (Step 10); a one-shot `occurred_at`-ordered re-sequence is a documented follow-up if ever needed. **`alembic check` fallback:** if the ORM `Identity()` declaration drifts against the migration (autogenerate parity is the one unproven bit), replace with an explicit `CREATE SEQUENCE` + `server_default=text("nextval('runtime_events_seq'::regclass)")` and a matching model `server_default` (Task 1 gates on `alembic check` = clean). **Rejected:** a plain `Integer` (32-bit exhausts at ~2.1B events), `occurred_at`-only ordering (the exact skew/tie bug), a workspace-scoped counter (needless — a global monotonic seq is still monotonic within any workspace filter).
- **D-A2 — `durable=` flag, not "always raise."** The two same-session emitters gain `durable: bool = False`. When `durable=True` (only the state-recording terminal transitions: `step_completed`, `run_completed`), a DB-persist failure **propagates** so the state-change transaction aborts atomically — the system-of-record cannot silently gap. Redis publishing stays best-effort in both modes (a Redis hiccup must not fail a run). Default `False` preserves today's best-effort behavior for the ~15 non-lifecycle emits (`surface_created`, `run.awaiting_reauth`, etc.). **Rejected:** removing the try/except entirely (would make every best-effort emit fail-hard — destabilizing); a global "all emits durable" (over-broad — many emits are genuinely advisory). **Note the Step-4 session-poisoning lesson:** swallowing a flush failure is *actively harmful* when it leaves the session aborted — the caller's later `commit()` raises `PendingRollbackError`. `durable=True` surfaces the error at the right place instead.
- **D-A3 — Retention contract: `RuntimeEvent` is exempt from hard-deletion.** It is the durable system-of-record; hard-deleting it would make reconcile-from-event-log (Step 10) impossible. Today it is *already* never evicted (correction #7) — so the contract is a **documented invariant + a regression-guard test** asserting `EvictionService.run_full_eviction()` leaves `runtime_events` untouched. If bounded retention is ever needed it must be an **archive** (cold storage), never a hard-delete. **Rejected:** adding `RuntimeEvent` to the 90-day `_evict_old_events` set (destroys the record); silently leaving it undocumented (a future maintainer could add it to eviction unaware it is load-bearing).
- **D-B1 — Enrich only the two events the run-status projection needs.** `step_completed` (payload gains `status` = the read-back verdict status: `completed`/`completed_unverified`/`partially_completed`) and `run_completed` (payload gains `status` = `completed`/`partially_completed`). The projector treats `event_type` as the status fallback for pre-enrichment events (`run_completed`→`completed`, `run_failed`→`failed`, `run_cancelled`→`cancelled`) so the replay is backward-compatible with the 392 existing thin events. **Rejected:** enriching every event type (unbounded — YAGNI; the spec asks to *prove* one projection is event-sourceable, not to event-source everything); event-sourcing `get_agent_workload` (its source is `ModelCall`, wholly non-event-driven) or `get_active_agents` (needs full `input_data` — out of scope).
- **D-B2 — The replay projector orders by `seq`, and lives on `RuntimeProjectionService`.** `rebuild_run_projection(run_id)` folds `WHERE workspace_id=? AND run_id=? ORDER BY seq` events into `{status, total_steps, completed_steps, progress_pct}`. Ordering by `seq` (not `occurred_at`) is the whole point — the test seeds events with tied `occurred_at` and asserts the rebuild still matches. It is a **read/analytics** method (belongs with the other projections), explicitly NOT execution truth. **Rejected:** a separate `runtime_replay.py` module (the projector *is* a projection — cohesion says keep it with its siblings); ordering by `occurred_at` (defeats the seq column's reason to exist).
- **D-C1 — One 1:1 `task_run_details` table, `run_id` as PK/FK CASCADE.** Holds `policy_decision` (durable), `context_pack` + `context_pack_expires_at` (TTL'd). Using `run_id` as the PK makes 1:1 structural (at most one detail per run) and CASCADE-deletes with the run. Keeping both fields in **one** table (vs two tables) is justified because TTL is enforced by **NULLing the `context_pack` column** (not deleting the row), so `policy_decision` survives context-pack expiry in the same row. **Rejected:** two tables (`run_policy` + `run_context`) — needless when column-level NULLing expires half the row cleanly; a synthetic `detail_id` PK + unique FK (redundant — `run_id` is already unique-by-construction).
- **D-C2 — "by-ref + TTL" = a side table keyed by `run_id` with `context_pack_expires_at`.** Relative to the slim `TaskRun` row, the pack is now *by reference* (dereferenced by `run_id`, not inlined). The TTL (`CONTEXT_PACK_TTL_DAYS = 30`, matching the summary-surface retention) is enforced by a new eviction sweep that NULLs expired packs. The **dereference/expiry render fallback** is `get_context_pack(run_id)` returning `None` when the row is absent OR `context_pack IS NULL` (expired) OR `expires_at < now()` — and every reader already coerces `... or {}`. **Rejected:** Redis-only storage (the pack must be queryable for UI history after any Redis TTL; Postgres + `expires_at` gives durable-until-expiry with a clean fallback); no TTL (unbounded growth of heavy JSONB — the very bloat we're removing).
- **D-C3 — 30-day context-pack TTL, reset on refresh; `policy_decision` never expires.** Context packs are ephemeral working context: a completed run doesn't need it for execution, and a paused run's stale-context refresh (`graph_executor.py:410`) *rewrites* the pack (resetting `expires_at`). 30 days comfortably exceeds any paused-run window. `policy_decision` is a durable audit/evidence fact (read by `evidence_bundle`) → no TTL. **Rejected:** a short TTL (risks NULLing an active paused run's pack — though the refresh rebuilds from scratch gracefully, 30 days removes the concern); expiring `policy_decision` (it is evidence, not working state).
- **D-C4 — Expand-contract with dual-write + dual-read, contract drops the columns.** The rebuild branch lands together, but the *tasks* honor the textbook sequence the spec requires: **expand** (C1: create table + backfill), **dual-write** (C3: writers write BOTH the old column AND the detail store — so a mid-window code rollback still reads the old column), **dual-read** (C4: readers read the detail store, fall back to the old column for any not-yet-migrated row), **contract** (C5: drop the old columns + remove the transitional old-column writes/reads; downgrade re-adds + copies back from the detail). **Pre-cutover event-log/row-gap handling:** a run in flight during the expand window with no detail row yet is covered by the dual-read old-column fallback; after contract, an absent detail dereferences to the render fallback (`{}`). **Rejected:** detail-only writes with an immediate drop (loses mid-window rollback safety — the spec explicitly wants dual-write/dual-read demonstrated).
- **D-C5 — The cost rollup stays on `TaskRun`; only `context_pack_json` + `policy_decision` move.** Per §4.8 and correction #2 — the hot history-list reader depends on the no-JOIN denormalization. This plan touches neither the rollup columns nor their readers/writers. **Rejected:** moving the rollup to the detail table (re-introduces a JOIN on the extremely-hot `routes_history` list path — explicitly forbidden by the spec).
- **D-Scope — Explicitly OUT of Step 5** (deferred to later steps, confirmed not built here): the `AsyncPostgresSaver`/dual-runtime execution cutover, single-flight lease, `durability="sync"` write nodes, and reconcile-from-event-log **execution** (Step 10 — Step 5 only makes `RuntimeEvent` *recordable* with `seq` so Step 10 *can* reconcile); the chat-path Deep Agents cutover + unified gate + write lock (Step 6); per-step idempotency keys (already built in Step 1); event-sourcing the workload/active-agents projections (different sources, YAGNI).

## In-flight-run / migration posture (spec §6 requires this per schema-touching step)

Three migrations, each additive-then-reversible:

- **Migration 1 (`a5f1c2d3e4b6`, Task 1) — `runtime_events.seq`.** `ADD COLUMN … GENERATED BY DEFAULT AS IDENTITY NOT NULL` — Postgres backfills every existing row atomically (proven by spike). **In-flight posture:** additive; a run mid-flight when this deploys keeps emitting events that now receive server-assigned `seq` — no drain needed. **Resume-across-deploy:** a paused run resumed after deploy emits its next event with a monotonic `seq` ordered after all pre-deploy events (the identity counter continues) — Task 1's real-DB test asserts inserts across a session boundary stay monotonic. `downgrade()` drops the column (identity + index go with it).
- **Migration 2 (`b6c2d3e4f5a7`, Task 6, part of C1) — `task_run_details` + backfill.** `create_table` then `INSERT … SELECT` from `task_runs` where either field is non-null (sets `context_pack_expires_at = now() + 30 days` for backfilled packs). **In-flight posture:** additive; the old columns still exist and are still read/written until contract, so an in-flight run is never invalidated. **Resume-across-deploy:** a run created before this migration has its detail backfilled by the migration; a run created between deploy and its first write is covered by the dual-read old-column fallback (Task 9's test asserts a run with no detail row renders context as `{}`). `downgrade()` drops the table.
- **Migration 3 (`c7d3e4f5a6b8`, Task 10, part of C5) — drop `task_runs.context_pack_json` + `policy_decision`.** Only after dual-write (C3) + dual-read (C4) land, so the detail table is authoritative. **In-flight posture:** a run mid-flight has already had its detail written (dual-write) and backfilled (migration 2), so dropping the old columns loses nothing. `downgrade()` re-adds both nullable columns and `UPDATE … FROM task_run_details` copies the data back — a proven round-trip.

**Shared write semantics before the dual-runtime window (spec §6):** the `seq` column + transactional event persistence make the event log a faithful record *before* Step 10's dual-runtime window, so whichever runtime writes events shares the ordering + atomicity contract. `RunDetailStore` is the single owner of `context_pack`/`policy_decision` writes, so both runtimes route through one supersede-free upsert.

## Data-migration / backfill plan (spec §6 — expand-contract, dual-read, pre-cutover gap)

| Phase | Task | Old columns | Detail table | Readers |
|-------|------|-------------|--------------|---------|
| **Expand** | C1 (Task 6) | present, read+written | created + backfilled from existing rows | old columns |
| **Dual-write** | C3 (Task 8) | still written | also written (fresh writes) | old columns |
| **Dual-read** | C4 (Task 9) | still written (transitional) | authoritative | detail-first, **fall back to old column** |
| **Contract** | C5 (Task 10) | **dropped** (model + migration) | authoritative | detail-first, **fall back to `{}`/None** (old-column read removed) |

**Pre-cutover gap:** any run whose detail row is missing (in-flight during expand, or a race) is handled at read time — dual-read falls back to the old column (pre-contract) or the empty render fallback (post-contract). No run is ever invalidated; context simply renders empty in the worst case, which every reader already tolerates (`... or {}`).

```python
    async def rebuild_run_projection(self, run_id: str) -> dict:
        """Reconstruct a run's status/progress projection from the runtime_events log
        ALONE, ordered by the monotonic ``seq`` (Step 5 §4.8, D-B2).

        Folds step_started/step_completed/run-terminal events into
        {status, total_steps, completed_steps, progress_pct}. ``status`` comes from the
        run-terminal event payload (enriched, Task 4), falling back to the event type
        for pre-enrichment events. completed_steps counts step_completed events whose
        payload status is a TERMINAL_SUCCESS (matches get_active_runs()'s live count).
        Read/analytics only — NOT execution truth.
        """
        rows = (
            await self._db.execute(
                select(RuntimeEvent)
                .where(
                    RuntimeEvent.workspace_id == self._workspace_id,
                    RuntimeEvent.run_id == run_id,
                )
                .order_by(RuntimeEvent.seq)
            )
        ).scalars().all()

        status: str | None = None
        started: set[str] = set()
        completed: set[str] = set()
        for e in rows:
            p = e.payload or {}
            sid = p.get("step_id") or e.step_id
            if e.event_type in ("step_started", "tool_call_started") and sid:
                started.add(sid)
            elif e.event_type == "step_completed" and sid:
                if p.get("status", "completed") in TERMINAL_SUCCESS:
                    completed.add(sid)
            elif e.event_type in _EVENT_TYPE_TO_RUN_STATUS:
                status = p.get("status") or _EVENT_TYPE_TO_RUN_STATUS[e.event_type]

        total = len(started)
        done = len(completed)
        return {
            "run_id": run_id,
            "status": status,
            "total_steps": total,
            "completed_steps": done,
            "progress_pct": round(done / total * 100) if total else 0,
        }
```

> **Note:** `get_active_runs()` counts `total_steps` from `TaskStep` rows and `completed_steps` from `s.status in TERMINAL_SUCCESS`. The rebuild counts `total_steps` from distinct started step_ids and `completed_steps` from `step_completed` events with a TERMINAL_SUCCESS status — so the test seeds one `step_started` per step to match `total_steps`. This parity is asserted by `test_rebuild_matches_live_read`.

```python
"""RunDetailStore — the single owner of the run-detail facts extracted off the hot
TaskRun row (Step 5 §4.8, one-owner-per-fact): policy_decision (durable) and
context_pack (heavy, ephemeral, TTL'd with a dereference/expiry render fallback).

Both fields live on the 1:1 ``task_run_details`` row keyed by run_id. Writes upsert
(a run may write policy_decision at creation and context_pack right after, or refresh
the pack later). ``get_context_pack`` applies the expiry fallback: an absent row, a
NULLed pack, or an expired pack all dereference to None so every reader's ``... or {}``
renders gracefully.
"""

from __future__ import annotations

from datetime import datetime, timedelta, timezone

from sqlalchemy import select
from sqlalchemy.dialects.postgresql import insert as pg_insert
from sqlalchemy.ext.asyncio import AsyncSession

from src.models.task_graph import TaskRunDetail

CONTEXT_PACK_TTL_DAYS = 30


class RunDetailStore:
    def __init__(self, db: AsyncSession) -> None:
        self._db = db

    async def upsert_context_pack(
        self, run_id: str, workspace_id: str, pack: dict, ttl_days: int = CONTEXT_PACK_TTL_DAYS
    ) -> None:
        """Store the context pack by-ref with a TTL (resets expiry on each write)."""
        expires_at = datetime.now(timezone.utc) + timedelta(days=ttl_days)
        stmt = (
            pg_insert(TaskRunDetail)
            .values(
                run_id=run_id,
                workspace_id=workspace_id,
                context_pack=pack,
                context_pack_expires_at=expires_at,
            )
            .on_conflict_do_update(
                index_elements=["run_id"],
                set_={"context_pack": pack, "context_pack_expires_at": expires_at},
            )
        )
        await self._db.execute(stmt)

    async def upsert_policy_decision(
        self, run_id: str, workspace_id: str, decision: dict
    ) -> None:
        """Store the durable policy decision (no TTL)."""
        stmt = (
            pg_insert(TaskRunDetail)
            .values(run_id=run_id, workspace_id=workspace_id, policy_decision=decision)
            .on_conflict_do_update(
                index_elements=["run_id"], set_={"policy_decision": decision}
            )
        )
        await self._db.execute(stmt)

    async def get_context_pack(self, run_id: str) -> dict | None:
        """Dereference the context pack; None if absent, NULLed, or expired (fallback)."""
        row = (
            await self._db.execute(
                select(TaskRunDetail).where(TaskRunDetail.run_id == run_id)
            )
        ).scalar_one_or_none()
        if row is None or row.context_pack is None:
            return None
        if row.context_pack_expires_at is not None:
            expires = row.context_pack_expires_at
            if expires.tzinfo is None:
                expires = expires.replace(tzinfo=timezone.utc)
            if expires < datetime.now(timezone.utc):
                return None
        return row.context_pack

    async def get_policy_decision(self, run_id: str) -> dict | None:
        row = (
            await self._db.execute(
                select(TaskRunDetail).where(TaskRunDetail.run_id == run_id)
            )
        ).scalar_one_or_none()
        return row.policy_decision if row is not None else None
```
